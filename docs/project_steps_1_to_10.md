## Step 1 — Decision, scope, alternatives

**Problem statement.** This project ranks ten proposed teaching-resource
improvement actions for the foundations of a Data Structures course, so that a
course instructor or teaching assistant with limited time can decide which
action to prepare first. A higher closeness score means *prepare this action
earlier*, under the four stated criteria. The ranking supports a decision; it
does not estimate learning gains or the probability that an intervention works.

**Scope.** Topics that underpin a first Data Structures course (recursion,
memory/pointers, algorithm analysis, correctness, abstraction). Course-level,
no individual students. Locality: a generic Data Structures course; the expert
ratings come from a 2008 US Delphi study (see limitations).

**Alternatives (actions, not existing conditions).** Each action = a resource
type applied to one topic. The barrier→action type reuses the lookup already in
the repo (`recommendations.py`); the barrier assignment per topic is an
**ASSUMPTION**.

| ID | Alternative (action – topic) |
|---|---|
| A1 | Interactive visualization or animation – Recursion, tracing and designing |
| A2 | Interactive visualization or animation – Memory model, references, pointers |
| A3 | Worked examples and graded practice – Recursive algorithms |
| A4 | Revised notes and step-by-step explanations – Recurrence relations |
| A5 | Revised notes and step-by-step explanations – Order of growth |
| A6 | Short instructional video – Algorithm analysis |
| A7 | Self-assessment quiz with explanations – Algorithm correctness |
| A8 | Concept map or diagram – Recursive definitions |
| A9 | Worked examples and graded practice – Abstraction / pattern recognition and use |
| A10 | Self-assessment quiz with explanations – Primitive vs. reference variables |

Out of scope: choosing the best *set* of actions under a budget (costs and
overlaps are not modelled), validating against student outcomes.

## Step 6 — Orientation and normalisation (crisp baseline)

Per the brief: benefit criteria `r = (x − min)/(max − min)`; cost criteria
(C4) `r = (max − x)/(max − min)`. Column ranges (central values):
C1 70–92, C2 45–88, C3 21–80, C4 11–55.

Worked example, A1:
- C1: (92 − 70)/(92 − 70) = **1.0000**
- C2: (78 − 45)/(88 − 45) = 33/43 = **0.7674**
- C3: (80 − 21)/(80 − 21) = **1.0000**
- C4 (cost): (55 − 51)/(55 − 11) = 4/44 = **0.0909**

## Step 7 — Fuzzy representation

Only C1 and C2 get a spread, because only they have evidence of disagreement
(assessor disagreement, as listed in the brief):

`x̃ = (l, c, u) = (mean − SD, mean, mean + SD) × 10`, clipped to the scale.

This is an **ASSUMPTION** about how to read a Delphi SD as a plausible range
(±1 SD). C3 and C4 stay crisp, i.e. degenerate (x, x, x), because inventing a
spread for synthetic numbers would be exactly the "±10 %" shortcut the brief
forbids.

Example, A1 C1: (9.2 − 0.9, 9.2, 9.2 + 0.9) × 10 = (83, 92, 100).

## Step 8 — Weights

- **Baseline:** equal, w = (0.25, 0.25, 0.25, 0.25); w ≥ 0, Σw = 1.
- **Alternative:** CRITIC (Diakoulaki 1995), computed from the normalised
  matrix: (0.2826, 0.2204, 0.1906, 0.3064). CRITIC reflects dataset contrast
  and correlation, not social importance.
- **Sensitivity scenarios:** one criterion at 0.4, the rest at 0.2.
- Do not tune weights to produce a winner.

## Step 9A — TOPSIS (crisp baseline), worked example for A1

1. v = w·r = (0.25, 0.1919, 0.25, 0.0227)
2. Positive ideal v⁺ = (0.25, 0.25, 0.25, 0.25); negative ideal v⁻ = (0, 0, 0, 0)
3. D⁺ = √[0² + 0.0581² + 0² + 0.2273²] = **0.2346**; D⁻ = √[0.25² + 0.1919² + 0.25² + 0.0227²] = **0.4029**
4. C = 0.4029 / (0.2346 + 0.4029) = **0.6320** → rank 2

(0.7388, 0.6179, 0.1483) exactly in the reference script.

## Step 9A — Fuzzy TOPSIS (Chen variant), worked example for A1

**TO VERIFY every formula below against the original paper before using it.**
Normalisation: benefit `(a/c*, b/c*, c/c*)` with `c* = max u`; cost
`(a⁻/c, a⁻/b, a⁻/a)` with `a⁻ = min l`. Weighted `ṽ = w·r̃`. Ideals (1,1,1) and
(0,0,0). Vertex distance `d = √[((Δl)² + (Δc)² + (Δu)²)/3]`; distances summed
over criteria; `CC = D⁻/(D⁺ + D⁻)`.

A1: C1 (83, 92, 100)/100 → (0.83, 0.92, 1.00) → ×0.25 = (0.2075, 0.23, 0.25);
C2 (54, 78, 100)/100 → ×0.25 = (0.135, 0.195, 0.25); C3 crisp 80/80 = 1 → 0.25;
C4 cost 11/51 = 0.2157 → 0.0539.
D⁺ = 0.7710 + 0.8080 + 0.7500 + 0.9461 = 3.2751; D⁻ = 0.2298 + 0.1990 + 0.2500 + 0.0539 = 0.7327;
**CC = 0.7327 / 4.0078 = 0.1828**.

Fuzzy closeness values are small because Chen's normalisation divides by the
column maximum rather than rescaling to [0, 1]. Compare *ranks*, not raw values,
across variants.

## Step 10 — Research extension and controlled comparison

Change exactly one thing: the **spread on C1 and C2**.
- Model E0: Chen TOPSIS with degenerate numbers (l = c = u).
- Model E1: Chen TOPSIS with the (l, c, u) numbers of Step 7.
Same normalisation, weights, ideals, distance. (Comparing E1 to the crisp
min–max TOPSIS would change two things at once — normalisation and spread —
so that comparison is reported separately and labelled as such.)

Mamdani role: the repo's existing Mamdani engine scores each action from
(difficulty, importance, resource gap) mapped to its three inputs. It ignores
effort, so it is a non-linear comparison, not a competitor on equal terms.
